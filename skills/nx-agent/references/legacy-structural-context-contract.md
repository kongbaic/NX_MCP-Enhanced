overview 时才使用“完整工程图 + 当前 target region 矩形框选”的 region-specific image；仅当 template 的 view_kind 仍为 null 时，Agent 才必须判断框选 region 属于哪个正投影视图，而不是把每个 deterministic region 假设成独立 view。矩形框只用于 region→view 归属，不是尺寸标注读取边界：只要某个明确 overall 尺寸位于同一 query image 中、能唯一归属于该框选 region 所属的同一个正投影视图，并且尺寸线确实跨越该视图完整外包轮廓，就允许写入 overall_dimension_facts，即使尺寸文字或尺寸线画在红框外。禁止读取属于其它视图的 overall；归属不唯一则 unresolved。旧 reader-input 没有 structural_context_path 时才兼容使用 region crop。**该 JSON 自带 `answer_template`；Agent 必须**原样复制 answer_template，并且只允许写入当前 fresh-hybrid-run-directory 内固定路径 `structural-context-answers.json`**，禁止把其它目录/上一轮 answers 传给 resume，禁止自行设计 schema 或字段，且顶层 `schema` 必须保持 `structural-context-answers-v1`。每个 answer 的 `query_id` 与顶层 `evidence` 必须保持模板原值；只允许填写 `view_kind`（仅 `front` / `side` / `top`，无法唯一判断则保持 null）、当前 query 视图直接标出的 `overall_dimension_facts`（每项固定为 `axis` + 正数 `value` + `evidence:[原样 evidence_label]`）、必填的 `rotational_symmetry` 显式判定以及 `unresolved`。对已解析且准备继续的 answer，`rotational_symmetry` 只能是 `{"status":"established","basis":"centerline","centerline_direction":"horizontal|vertical","evidence":[原样 evidence_label]}`、`{"status":"established","basis":"axial_section_symmetry","evidence":[原样 evidence_label]}` 或 `{"status":"not_established","evidence":[原样 evidence_label]}`；字段省略不是 not_established，schema 必须拒绝。模板中的 null 只用于 pending/unresolved：若视觉上无法完成该判定，保持 null 并写入 unresolved，本轮 fail-closed，禁止增加 unknown/uncertain 状态继续执行。只有当完整工程图明确且唯一表达整件绕某一可见工程轴回转时才允许 established。**不要求图纸额外打印 X/Y/Z 轴名**。允许两类 established 视觉依据：①**中心线依据**：纵向正投影或 axial/longitudinal section 中存在贯穿主要主体的明确整件中心线，且主要阶梯/圆柱主体段由围绕该中心线成对出现的相对同轴轮廓边/肩部表达回转体；②**无中心线轴向剖视依据**：query 通过剖面线/剖切语义明确属于 axial/diametral section，主要材料轮廓与各阶梯/圆柱主体段围绕一条唯一的剖面对称轴成对出现，可唯一确定回转轴方向，即使图中没有画出中心线也允许 established。第二类只适用于明确剖视，不适用于普通非剖视镜像轮廓。**连续实线的物体轮廓/边界绝不能冒充中心线。**Agent **禁止填写 X/Y/Z 回转轴，也禁止填写无中心线轴向剖视的 horizontal/vertical 或 left_right/top_bottom 方向**。centerline basis 仅可报告明确绘制中心线的 `centerline_direction=horizontal|vertical`；axial_section_symmetry 只报告剖视回转语义本身。该分支的轴方向必须来自 query 自带的 `deterministic_profile_symmetry_axis`，它由 Reader prep **优先使用已识别的 structural physical profile edges 做至少两对独立镜像拓扑一致性判定；这些 profile-edge candidates 必须来自本轮 RawEvidence 的 region-scoped H/V 结构线库存，dimension witness 只能追加 provenance，不能作为库存的唯一来源。多个镜像边对必须对同一视觉中点形成 midpoint consensus；未配对的候选线不作为回转反证，因为尺寸线/标注线可能与实体轮廓同处一个 deterministic region**；只有 profile-edge 证据不足时才回退到当前 region raster 的多阈值双边拓扑一致性判定。两条路径都只分类 horizontal/vertical，不产生任何工程尺寸或坐标；hint 缺失时必须 unresolved。若 query 还带 `deterministic_profile_symmetry_overlay="blue_dashed_topology_axis"`，则 `image_path` 中会在该确定性候选轴位置绘制蓝色虚线并标注 `TOPOLOGY SYM AXIS`。**这条蓝色虚线只是 Reader 的视觉定位辅助，不是原图中心线，绝不能作为 `basis:"centerline"`，也不能单独证明回转。**Agent 必须沿该蓝色轴检查主要实体轮廓/肩部是否成对出现，并结合剖面线、剖切或 axial/diametral section 语义判断。**若当前区域明确属于轴向/直径剖视，且主要实体轮廓围绕该候选轴成对出现，则不得仅因为原图没有绘制中心线就判为非回转或 deferred；应报告 `{"status":"established","basis":"axial_section_symmetry",...}`。**普通非剖视的镜像对称仍不足以建立回转。assembler 再按 `view_axis_map` 得到工程轴：front horizontal→X / vertical→Z，side horizontal→Y / vertical→Z，top horizontal→X / vertical→Y。该判断属于工程制图拓扑语义，禁止测像素距离、禁止把视觉“等距”换算成工程值。普通镜像对称、只有中心线但无成对同轴回转轮廓、外观“像回转件”、连续实线冒充中心线或参数名猜测都不足以 established。**若当前红框 region 明确只有规格表、BOM、标题栏或其它文字/参考数据，完全不包含零件正投影几何，则它不是 front/side/top 视图：必须保持 `view_kind:null`、`overall_dimension_facts:[]`、`rotational_symmetry:null`，并在 `unresolved` 中仅写精确 code `non_geometric_reference_region`；顶层 `evidence` 仍保持模板原值。该 code 只允许用于无几何 reference region；若 query 带有 `labeled_dimension_targets` 或 `accepted_linear_span_lower_bounds`，则禁止使用该 code，必须按正常几何 query fail-closed。deterministic profile symmetry hint 只是 candidate-only 的视觉定位辅助，不能把规格表/BOM 强制升级成几何视图；若 Agent 直接看图确认该红框确实是纯表格/BOM/文字参考区，仍允许返回 `non_geometric_reference_region`。Assembler 会跳过该 region 的 view mapping，但 Hybrid OCR/后续 Reader 仍可保留其文字/规格证据；Agent 不得因为它不是视图而把整轮 structural context 判死。** **当前 region 只有尺寸文字/引线/局部标注、没有足够零件几何用于回转判断时，必须写 `rotational_symmetry:null` 并在 `unresolved` 中仅写 `rotational_symmetry_not_visible_in_region`；这是 region-local deferred observation，不等于 `not_established`，也不能自己产生 rotational fact。assembler 只允许该唯一 code 跨 region 延期汇总；若其它 region 没有 established 回转证据且第三轴仍缺失，仍必须 fail-closed。其它任何 unresolved 仍立即终止。not_established 不是“没看出来”的兜底值**：只有 query 明确显示整件不具备回转对称时才允许使用；若既没有足够 established 证据，也没有明确反证，必须保持 rotational_symmetry=null、写 unresolved 并 fail-closed。**Agent 禁止据此手工补第三轴 overall；确定性闭合固定为：rotation X ⇒ Y=Z，rotation Y ⇒ X=Z，rotation Z ⇒ X=Y。缺失第三轴只允许由后续 deterministic finalizer 从一个直接 transverse overall + rotational_symmetry_axis 推导，并保留 derivation provenance。****若当前 query 带有 `accepted_linear_span_lower_bounds`，这些值来自本轮 Hybrid OCR 已接受的同 region、同视觉方向线性尺寸，仅作为 overall 的工程下界，不代表系统已经判定哪个尺寸是 overall。Agent 若视觉上决定填写某方向的 `overall_dimension_facts`，其 value 绝不能小于该方向的 `minimum_value`；否则说明把更小的局部/次级尺寸误当成整体尺寸，必须重新核对当前 query image，而不是继续写入较小值。该约束比较的是 OCR 工程尺寸值，不使用 pixel→mm。** **局部尺寸不得冒充 `overall_dimension_facts`：只有明确跨越当前视图完整零件外包边界/整体轮廓两端的直接 overall 标注才可写入；局部链尺寸、孔/圆中心距、中心到边、半径/直径、角度以及仅覆盖局部轮廓的线性尺寸，即使数值较大或恰好为 70/50，也禁止提升为 overall。若图中没有明确 overall 标注，对应 axis 不写 fact，保持 unresolved；不得为了让 Hybrid Adapter 继续而补值、算术推导或用像素估计。****overall fact 的 axis 禁止由 Agent 自行推断，必须严格使用 queries JSON 的 `view_axis_map`：front horizontal=X / vertical=Z；side horizontal=Y / vertical=Z；top horizontal=X / vertical=Y。**view_kind 已确定时清空模板中的 `pending_structural_visual_read`；view_kind 无法确定时保留/改写 unresolved 且不得写 overall_dimension_facts。禁止增加其它字段。**若 query 带有 `labeled_dimension_targets`，则这是 Hybrid OCR 已经读出正数毫米值、但尚无唯一 DG owner 的受限关系查询；`answer_template` 会为其预置 `labeled_dimension_decisions`。answer_template 中若某个 labeled decision 已是 `status=resolved`，且对应 target 带有非空 `deterministic_relation_seed`，说明 Reader 已经凭独立证据建立了关系：可能是 short-dimension witness + 内部轮廓确定的局部 `between_profile_boundaries`，也可能是单条 OCR 尺寸线两端分别唯一接触材料相反两侧的整件外表面、从而确定的 `overall_extent`。仅有 region-relative extrema、规格字段名称或数值大小，都不能自动推断整件 overall。Agent 必须原样保留该 decision，禁止重新视觉判断、禁止改写 direction/relation，也不要为它补 profile_transition_geometry / symmetry_scope。只有模板仍为 `status=unresolved` 的 target 才需要视觉判断。Agent 必须覆盖全部 target，禁止新增 target、禁止遗漏 target，并且禁止改写 OCR 给出的 value：decision schema 根本不允许提交数值。对于仍待判断的 target，只允许直接观察当前 query.image_path，填写 `visual_direction=horizontal|vertical` 与关系族：`overall_extent`、`overall_min_to_profile_transition`、`overall_max_to_profile_transition`、`between_profile_boundaries`；局部关系的 `profile_transition_geometry` 与 `symmetry_scope` 只是可选描述元数据；看不清时保持 hint 冲突，必须 fail-closed：写 `status=unresolved`，并把 `visual_direction/relation/profile_transition_geometry/symmetry_scope` 全部置为 null，只在 reason 中记录方向冲突；禁止为了“保留 hint”而把 visual_direction 填进 unresolved decision。** 关系族也必须按这条方向解释：只有某个箭头端点明确落在该方向上的整件 overall 外包边界时，才允许 `overall_min_to_profile_transition` / `overall_max_to_profile_transition`；两个箭头都落在局部/内部 profile boundary 时必须用 `between_profile_boundaries`。**不得根据参数字母名称、行业习惯或数值大小猜关系；不得测像素距离或把像素换算成毫米。若关系不能唯一看清，保持 `status=unresolved`、所有语义字段为 null，并填写 reason；`pending_labeled_dimension_relation_read` 只是模板占位，resume 前必须替换为真实 Structural Reader 阶段判断其它 feature inventory、cross-view identity、未列出的 feature/local value、精确 dimension endpoint ownership、start side、termination 或 pixel→mm；无法唯一判断就写 unresolved，不得猜。
